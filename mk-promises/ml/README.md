# מודל סיווג התבטאויות בוועדות מול הבטחות

מודל שמקבל זוג **(הבטחה, קטע מפרוטוקול ועדה)** ומחזיר אחת משלוש תוויות, כמו הקטגוריות באפליקציה:
`support` (מקדם את ההבטחה), `contradict` (סותר אותה), `context` (לא נוגע בה).

הארכיטקטורה:

```
זוג הטקסטים -> [מקודד LLM] -> וקטור לכל טוקן -> [BiLSTM] -> [קשב + max pooling] -> [DNN: 256 -> 128] -> 3 מחלקות
```

הפלט הוא **הצעה לבדיקה אנושית**. הוא לא קובע סטטוס להבטחה, והאפליקציה ממשיכה לקבל את הסטטוס מהמשתמש בלבד.

## מצב הקוד

- הקוד נבדק מול **נתוני דמה בלבד** (תבניות שנכתבו ידנית, `synthetic.py`) ומול BERT זעיר עם משקולות אקראיות. הבדיקות מוכיחות שהצנרת עובדת (צורות, גרדיאנטים, שמירה וטעינה, אימון והרצה). הן **לא** מוכיחות דיוק, והציון על נתוני הדמה חסר משמעות.
- **לא אומן שום מודל על פרוטוקולים אמיתיים.** אתר הכנסת לא היה נגיש מהסביבה שבה נכתב הקוד, ואין תיוג אנושי של זוגות.
- **לא נטען מודל LLM מאומן.** `huggingface.co` לא היה נגיש. המקודד `hf` נבדק רק עם מודל מקומי זעיר. המקודד `hashed` אינו LLM (הטמעות n-gram שמאומנות מאפס) והוא קיים להרצה אופליין ולבסיס השוואה.
- `fetch_protocols.py` ו-`protocol_parser.py` נבדקו מול שרת דמה מקומי וטקסט לדוגמה, לא מול הכנסת. שמות הישויות והשדות (`KNS_DocumentCommitteeSession`, `GroupTypeDesc`, `FilePath`) וצורת הפרוטוקול (כותרת דובר בשורה נפרדת שמסתיימת ב-`:`) לקוחים מתיעוד ציבורי ועלולים להצריך תיקון.

## קבצים

| קובץ | תפקיד |
|---|---|
| `fetch_protocols.py` | מוריד פרוטוקולים של ועדה לטווח תאריכים וממיר לטקסט. **להריץ במחשב שלך, מחיבור ישראלי.** |
| `fetch_bills.py` | לולאת `$skip` (0, 100, 200...) על `KNS_Bill` עד עמוד ריק, שומר JSONL. **להריץ במחשב שלך, מחיבור ישראלי.** |
| `protocol_parser.py` | מפצל פרוטוקול טקסט לדוברים ולהתבטאויות, ומתאים דובר לשם ח"כ |
| `model.py` | המקודדים, ה-BiLSTM וראש ה-DNN, שמירה וטעינה |
| `train.py` | אימון והערכה (פיצול לפי ח"כ, כדי שלא יימדד על דוברים שאומנו עליהם) |
| `predict.py` | הרצה על פרוטוקול והבטחה, פלט JSONL של הצעות |
| `synthetic.py`, `test_ml.py` | נתוני דמה ובדיקות צנרת |

## שימוש

```bash
pip install torch transformers          # transformers נדרש רק למקודד hf

# 1. הורדת פרוטוקולים (במחשב שלך, מישראל)
python fetch_protocols.py --committee 2211 --from 2026-04-27 --to 2026-10-27 --out protocols
#    אם לא נמצא כלום: --list-types, ואז --doc-type עם המילה הנכונה

# 2. אימון על זוגות מתויגים ידנית (JSONL)
python train.py --data labelled.jsonl --encoder hf --hf-model dicta-il/dictabert --out run1

# 3. הצעות לפרוטוקול ולהבטחה
python predict.py --checkpoint run1/model.pt --protocol protocols/2026-05-04_123.txt \
    --promise "להגדיל את תקציב הביטחון" --source-url "<כתובת הפרוטוקול מ-manifest.json>"
```

פורמט `labelled.jsonl` (שורה לכל זוג):
`{"promise": "...", "utterance": "...", "label": "support|contradict|context", "group": "<שם הח"כ>"}`

## מה צריך כדי שזה יהיה שימושי

1. **תיוג.** צריך כמה מאות עד אלפי זוגות שתויגו ידנית, עם מחלקת `context` מייצגת. בלי זה אין מה לאמן.
2. **הבטחות 2022 מוקלדות עם מקור.** המודל משווה מול נוסח ההבטחה, ולכן הוא תלוי בניסוח שלה.
3. **בדיקת האיכות על ח"כים שלא הופיעו באימון.** `train.py` כבר מפצל כך, ועדיין צריך לבדוק ידנית דוגמאות מהפרוטוקול עצמו.
4. **שם מודל עברי.** ברירת המחדל `dicta-il/dictabert` היא הצעה שלא נבדקה כאן. אפשר להחליף ב-`--hf-model`.
